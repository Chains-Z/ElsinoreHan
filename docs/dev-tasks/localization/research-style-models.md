# AI 翻译风格、技能与模型调研

调研日期：2026-10-09。范围是英语游戏文本到简体中文的批量翻译；没有安装外部技能、调用翻译 API、读取凭证或发送游戏原文。网页读取失败的智谱页面通过只读 HTTP 获取其官方 `.md` 原文核实。

## 可复用的实践

已有项目采用的共同做法是：按场景分批，把角色、世界观、术语和相邻上下文放进提示词，逐条按稳定 ID 返回译文，再机械检查格式。文风需要具体规则及正反例；单说“信达雅”“专业游戏翻译”没有可核对的效果保证。这是从以下项目归纳的实施建议，不是有关“大多数人”的统计结论。

- [GalTransl 作者提示词](https://github.com/GalTransl/GalTransl/blob/main/GalTransl/Backend/Prompts.py)：有说话人时按对白、没有时按独白/旁白处理；分别传入历史译文、术语和风格指南，按 ID 逐句返回，保护系统标记。可借鉴数据契约，不能把其日译中专名策略直接用到本游戏。
- [AiNiee PromptBuilder](https://github.com/NEKOparapa/AiNiee/blob/main/ModuleFolders/Domain/PromptBuilder/PromptBuilder.py)：组合角色性格和说话方式、背景、风格、术语、翻译示例及上文。适合让 GLM 使用可配置的翻译规则，而不是只给孤立句子。
- [AiNiee 项目](https://github.com/NEKOparapa/AiNiee)：支持复杂长文本和自定义翻译/润色设置，是实际批处理工具候选；可借鉴工作流，不必为了风格控制从零实现整套翻译器。

| [腾讯 Hy-MT2-Translator](https://clawhub.ai/tencent-adm/skills/hy-mt2-translator-skill) | 腾讯官方模型卡链接了此技能 | 已确认官方链接；技能完整内容尚未审计，不列为可直接安装或适合 GLM 的结论 |

## 模型候选与证据边界

| 候选 | 官方核实 | 建议用途 |
| --- | --- | --- |
| GLM-5.3-Flash / GLM-5.3 | 官方当前目录列出这两类模型；均要求启用思考；旗舰支持 `reasoning_effort=low/high/max` | GLM 系列候选：Flash 先做成本及风格试译，旗舰可用同一批真实资料做质量对照；用户尚未最终选模型 |
| Qwen-MT-Flash / Qwen-MT-Plus | 翻译专用 API，支持术语、翻译记忆、领域与自定义风格；单轮，不接收 system 消息 | 云端翻译模型对照；需要单独适配 `translation_options`，不能机械复用 GLM 的 system/user 结构 |
| 腾讯 Hy-MT2-7B | 官方已提供 1.8B、7B、30B-A3B，且有风格、上下文、术语、结构化数据等提示示例 | 如希望本地离线且具备合适硬件，7B 是可测候选；硬件适配与运行速度尚未验证 |
| bilibili Index-Translate | 新发布的翻译专用模型系列，支持术语、文风、结构约束及长文本；有预览接口 | 可加进小样英中盲评。预览免费接口不等于稳定全量服务承诺 |

来源：[智谱官方模型目录](https://docs.bigmodel.cn/llms.txt)、[GLM-5.3](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)、[GLM-5.3-Flash](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[Qwen-MT](https://help.aliyun.com/zh/model-studio/machine-translation/)、[腾讯 Hy-MT2 模型卡](https://huggingface.co/tencent/Hy-MT2-7B)、[Index-Translate 作者仓库](https://github.com/bilibili/Index-Translate)。

上表是候选名单，不是排名。厂商公开的翻译基准、编程基准或“超过某模型”宣传不能证明《Elsinore》的角色对白更自然。尤其不能把编程能力、中文写作能力和忠实的游戏翻译能力划等号。

旧文章常推荐 HY-MT1.5 或要求 GLM 关闭思考；本次查看的官方资料已经更新。GLM-5.3 发送 `thinking.type=disabled` 会失败，应使用 `enabled`。先试 `reasoning_effort=low` 是本项目控制试译消耗的建议，不是经过实测的翻译最佳设置。思考 token、实际成本和完成率必须记录真实 usage。

## 给 GLM 的风格提示草案

以下是综合已有做法、针对游戏调整的草稿；尚未经过真实 GLM 试译。固定规则放入 system，具体场景、术语和带 ID 的记录放入 user。角色资料必须从游戏证据整理，不能让模型编造角色性格或剧情背景。

```text
你负责把《Elsinore》的英文游戏文本译成自然、准确的简体中文。

目标：玩家直接读懂对白、信息和操作提示。保持原意及人物口吻，中文句子要顺口。

忠实规则：
1. 完整保留谁对谁说、谁做什么、否定、条件、因果、时间先后、数量及不确定程度。
2. 传闻、猜测、愿望、反问、讥讽和假设保持原有立场。角色尚不知道的信息不得借背景补明。
3. 不添加原文没有的解释、情绪、动作、称呼或笑点。歧义不能解决时保留歧义，写到审校字段。
4. 术语和专名按给定表统一；未确认的新专名记录待审，不自定全局译法。

中文风格：
5. 对白按角色身份、关系和当下语气说话，优先常用词和自然短句。旁白、书信和菜单各用适合的语体。
6. 可以重组中文语序，在同一条记录内拆句；不要逐词套英语。检查机械的被动、名词化、过多的“的”和代词。
7. 为自然中文省略重复成分时，不能让人物指代、条件或关键线索含混。俚语按语境表达，双关不能自行改成另一条线索。
8. 游戏有莎士比亚背景。保留原文已有的古雅、戏剧感和人物差异，程度以当前英文为准：日常对白自然清楚，宫廷称谓和正式交谈稍庄重，戏中戏、祈祷、诗句和名句保留凝练及节奏。清晰可读优先，不把所有角色统一写成文言，不擅加当代网络梗，也不把粗犷口语改成雅言。
9. 完成后先单独读中文，修改拗口处；再逐句对照英文，检查新增、漏译和态度变化。

格式规则：
10. 只翻译 source 的可见文本。id、代码、变量、占位符、富文本标记及规定的换行标记原样保留。
11. 每条输入对应且只对应一条输出；不可串行、合并、漏行、改变 ID 或翻译只供参考的上下文。
12. 只输出约定的 JSON；译文里不写解释。确需审校的问题放在独立 issues 字段。
```

输入应分为 `context`（只读且不要求翻译）、`glossary`、`characters`、`records`。输出建议 `{"translations":[{"id":"原ID","target":"译文"}],"issues":[]}`。正式处理器需在本地验证这个契约，不能信任模型自行检查。

初期不要加几十页禁词；“进行”“被”等只是可能的翻译腔信号，有合理用法，不能机械删除。最有价值的 few-shot 是用户对真实游戏样本确认过的 5–10 组原文/认可译文。未经确认的演示句不得混入正式词表或宣称它们来自游戏。

## 小规模试译和盲评

建议从现有真实资料抽约 150 条，覆盖一个连续场景及其他角色、菜单和资料文本。不要只从去重字符串随机抽句；保留实际说话人和剧情路径，互斥分支不能假装为连续对话。按信息需要分批并加入相邻上下文，初始批量先从 10–20 条试起，再依据输出截断和漏行率调整；这是实验起点，不是固定行业标准。已制备 [本地 VNText 试译输入](../../../translation/pilot/README.md)，为保留完整脚本段落实际包含 217 条；该输入仍需确认分支路径，不代表完整上下文已处理。

使用 AiNiee 或 GalTransl 时应沿用所选后端的输入输出契约，上面的文风规则注入角色、背景和写作风格等配置。独立 API 示例的 JSON 结构不能直接替换工具原有格式提示。

建议第一轮比较 GLM-5.3-Flash、Qwen-MT-Plus 和 Index-Translate 预览：分别代表通用中文模型、专用翻译 API、强调文风和长文本的开源翻译模型，比较维度比只测同一家模型更有用。接口可用性和真实成本需在调用前核实；Index 预览不可用时可先测前两者。GLM-5.3 可作为对照 Flash 是否值得升级的补充；HY-MT2 只有在本地硬件适配有意义时加入。该组合是实验建议，不是已验证排名，也不要求用户此刻决定最终模型或渠道。所有模型接收相同英文、术语、场景背景和风格规则，记录模型 ID、参数、提示版本、原文哈希、usage、时延与重试。

评阅把模型名隐藏、候选次序打乱。先检查原文对应的准确性，再单独读中文检查自然度。用户只需先看 20–30 条有代表性的成对候选，确定喜欢的口吻；无需先完整人工审校一万多条才开始玩。

| 维度 | 判定重点 |
| --- | --- |
| 意义准确 | 否定、条件、时间、对象、情报线索和确定程度是否改变；实质误译优先修正 |
| 中文自然 | 是否拗口、机械代词、名词堆叠；不因为词藻多就得高分 |
| 人物口吻 | 同一角色是否稳定，身份、关系、情绪和讥讽是否保留 |
| 一致性 | 专名、称呼、物品、线索术语是否符合锁定表 |
| 格式 | ID 集合、占位符、标签、换行、空译与输出解析必须通过 |

自动检查只证明结构合格；另一个模型的打分也不能代替用户语感。润色保留原文并仅处理有问题条目，保留初稿和修订记录，防止“去 AI 味”时改掉游戏线索。风格确认后批量翻译，游玩中继续记录误译和溢出，不承诺所有分支都经过人工验证。
