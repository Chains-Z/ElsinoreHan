# 实现说明

## 精确编译与格式派生

已静态核实`Elsinore.Game.CompilerPasses::doTextReplacement`按顺序将以下九种子串替换为`—`：` -- `、` --- `、` - `、`-- `、`--- `、` --`、` ---`、`--`、`---`。顺序不可更换为通用破折号正则，例如`A---B`实际成为`A—-B`。中文不照搬英文标点替换，只共享同一份审定中文。

幽灵编译额外加一层`<i>…</i>`，保留原文内部强调。现有精确行高封套与日志终LF也从同一中文生成。个别历史英文空白别名保留准确源哈希，不扩展任意空白归一化。

`source_variant_generation.py`核对旧覆盖链的实际ID、源哈希、准确旧译，随后从规范译文生成目标；标签、占位符和各关系等式均须通过。旧覆盖链若被单边修改，导出失败并要求修改规范译文。读取规范文件是强制步骤，缺失时不退回旧双源模式。

`prepare_variant_generation.py`只用于首次迁移：关系组成连通分量，以当前实际运行源的已审译文作为权威，反向去掉编译封套，得到规范中文。若两个真实运行源将被改成不同文字则拒绝合并，须登记实际语境区别。格式循环、推导冲突和封套缺失也直接失败。

## 历史资料承接

冻结输入、raw、outputs、审计未改。旧校订与别名文件仍是历史阶段的不可变重放记录，其`target`不是今后要分别编辑的维护入口；合同中的`previous_target`同样是迁移前快照。当前最终`target`只由规范译文决定。

历史阅读稿与消费者生成器使用同一个派生模块，先按原顺序核对旧修订，再生成当前资源及运行译文。部分审查只含一端时仍核对该端准确旧值，不读取当前输出倒推答案。补齐love审查对既有结局阅读反馈的承接，消除“从政的人”在旧夹具中滞留为“政客”的问题。

迁移后的独立资源审查仍重新从真实游戏资源提取15,181组对白，核查全部708组成对源与33条显式运行别名；新出现的成对源必须纳入合同或语境例外。

## 范围

本轮修改导出与离线治理流程、预制词表及对应阅读稿，不修改运行插件、动态规则或游戏业务数据。安装包仍同时包含资源键、编译键等必要英文入口，但这些入口的中文由同一份规范译文产生。并非把必要的英文查找键删除，也不在游戏运行时再推导或联网翻译。
