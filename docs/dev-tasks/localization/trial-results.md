# 四模型真实游戏文本试译

2026-10-09：通过用户提供的百炼北京业务空间和一把 Key，复用固定版本 AiNiee-Next 完成四候选各 40 条真实试译，共 160 条译文。批量请求 16 次，按真实 usage 与保守单价折算 **0.121209 元**，未扣缓存及活动优惠；连通检查另计不足 0.001 元。没有查询用户余额或实际账单，不把这一数字当扣费记录。

本批建议优先考虑 **DeepSeek Flash 作为初稿候选**，GLM Flash 保留作局部文风对照。Flash 在生死、暂停状态及血亲范围上更稳，仍有“眼睛空了”“上帝不容”等直译问题。GLM 有些表达更自然，但出现主动暂停与补写夫君关系的问题。Pro 的价格更高，却没有避免这批最关键的生死误译，因此当前没有理由仅因其定位而选作主力。Qwen-MT 的专用接口需要进一步适配，当前结果不能推断其在原生翻译流程中的通用能力。

这只是单次 40 条小样的项目判断，未做重复采样、统计显著性检验或全量审读；没有锁定全量模型，也没有执行全量翻译。

## 关键句对比

以下省略号只省略展示；完整译句见全文对照。重点先看事实，再看中文自然度。

| 原文及含义 | DeepSeek Pro | DeepSeek Flash | GLM Flash | Qwen-MT Plus |
| --- | --- | --- | --- | --- |
| `he was. Is.`，承接前句 `dead`：过去死了，现在也是 | “他死了。也还活着” **反转** | “他确实死过。现在也死了” | “他是死了。现在也是” | “他确实死了。也活着” **反转** |
| `He is ... on pause.`：他处于暂停状态 | “他呢，怎么说，暂停了” | “可以说，他被暂停了” | “他嘛……是按下了暂停” **主体改变** | “他现在嘛……暂时停下了” 暂停含义变弱 |
| `the traitor is my own blood`：叛徒是血亲 | “自己的血亲” | “自己的血亲” | “我的血亲” | “我的亲兄弟” **无依据收窄关系** |
| `His eyes ... empty`：眼睛/眼神变得空洞 | “它们……空了” 机械、易歧义 | “它们……空了” 同样问题 | “变得……空洞了” | “它们……空洞了” 代词机械 |
| `art thou ashamed of me?`：觉得我丢人吗 | “你是羞于我吗” **中文搭配不成立** | “羞于和我在一起吗” 仍稍直译 | “羞于承认我是你夫君” **补写信息** | “你对我感到羞耻吗” 稍僵硬 |
| `No, sir, God forbid, but ashamed to kiss.`：绝不是嫌你丢人，只是害羞于接吻 | “上帝不许，是羞于亲吻” **易误读为禁令** | “上帝不容，只是羞于亲吻” **同样有风险** | “天理不容有此念头……罢了” 太拗口、解释增多 | “天哪，我只是不好意思亲吻” 此句较顺口 |
| `You sound terribly glum.`：听上去很沮丧 | “沮丧极了” | “闷闷不乐” | “情绪低落得很” | “糟糕透了” **弱化具体情绪** |

`God forbid` 是戏中戏里的强烈否认，不应按逐词义写成神禁止亲吻。此类惯用语与省略状态不能靠占位符检查解决。祈祷中的“满被圣宠”“你在妇女中受赞颂”有固定宗教语体依据，不因不日常就判成病句；也不能据此把其他普通对白古化。

风格上，没有候选把全篇普遍译成文言。主要风险是局部直译、省略句误读、增译和词义收窄。“不要像 AI 说话”只能作为文风目标，实际流程还需可观察的检查项：人称/指代、肯定否定、生死及时态、亲属关系、可能性、惯用语、人物语气和富文本强调。

## 独立审读与比较边界

- [first审读](trial-review-first.md)：匿名输入，评阅 agent 继承本轮会话，不能称为严格盲评。最初审读的是工具转繁体版本，后已按冻结简体响应恢复；句子语义没有改写，报告保留当时证据。
- [second审读](trial-review-second.md)、[third/fourth审读](trial-review-third-fourth.md)：新建不继承会话的 agent，仅获得匿名源文/译文/背景，不提供模型身份，不读取其他候选或配置。此过程减少身份影响，仍是同类 AI 审读，不能替代人的语感和全量审校。
- 身份映射：first=DeepSeek Pro，second=GLM Flash，third=Qwen-MT Plus，fourth=DeepSeek Flash。映射在审读完成后才汇总。
- Qwen-MT 的请求经桥接合并 system/user 为单 user，并附 `translation_options`。实际响应把部分说明/术语/背景也翻译复述；上游成功取出最后一个正文 textarea，但额外输出增加用量且说明适配不理想。不能把当前输出当它采用原生 `domains`/`terms` 并只传源文后的最佳表现，也不为修接口再重付费试译同一 40 条。
- 当前 GLM 的姓名 metadata 多保留英文，正文仍由 manifest 绑定。后续补丁中的姓名应单独从固定表处理，不用重译正文来修这个字段。

## 已解决的执行问题

1. 新版 Key 含点号，旧匹配式曾截断并导致首次 DeepSeek Pro 连通失败。修复为完整本地读取并补 4 项回归，不暴露 Key。GLM 首次返回未开通，用户开通后同一 Key 成功。
2. 上游非交互启动仍要求 WebUI 包，触发 EOF；跳过传统 `translate --yes` 无关安装检查，未请求模型。
3. `round_limit=0` 会空跑，不能用 exit=0 作为成功证据；改为一轮，并同时检查新成功请求、完整数量与中文输出。
4. 上游 preset 默认繁体后处理；显式关闭。Pro 的 40 条从已冻结原始简体响应回收，不重复调用或改写措辞。
5. Flash 首 20 条缺 textarea 包装，工具判成未翻译。离线按真实原文和完整编号回收；后续仅给完全对齐、无解释的编号正文添加包装，账本保留原响应。
6. 续跑曾把“已有一批全部通过”误认成“预期三批完成”；改为核对完整批次集合，并补部分完成可续跑、全部完成拒绝重复付费的回归。Flash 后 20 条确实跳过已付费首批。
7. Windows 离线集成子进程曾用 GBK 解码 UTF-8 日志；测试捕获显式 UTF-8，属于验证框架编码修正，未触发模型重试。

这些修正改变执行与回收，不掩盖原始译文里的意义错误。运行缓存与下载依赖被 Git 忽略；原始请求账本、来源、最终结果及回收 provenance 保留。

## 验证完成口径与下一步

真实 LLM 链已完成：真实游戏资源 → 有来源的受控输入 → 现成 CLI → 用户配置的真实模型 → 冻结响应 → 160 条可追溯对照。19 项项目离线回归及 17 项现成执行器集成/预算/格式回归通过；离线假响应测试不算真实 LLM 调用。

这批模型译文尚未安装到游戏对白/资料页，不能称游戏汉化 E2E 通过。已完成的游戏验收仍是此前主菜单中文与后台静音设置组件导航；详见[技术验证](technical-probe.md)。后续消费链应使用本次冻结真实译文，在副本中做少量有记录的局部校订，再验证运行时文字加载、字体与排版，不重付费翻译测试夹具。

全量前先把省略状态、惯用否认、关系范围和“不补写剧情”写成少量明确规则；术语保持统一，按真实场景分块。先用候选生成可玩版本，再随游玩改漏译/错译，完整人工审校不是开始玩的前置条件。当前无须申请更多 API Key，也无须为离线翻译速度开 FlashX。
