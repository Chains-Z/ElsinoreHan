# 300 条扩展试译输入

本目录只制备真实源文，未读凭证、未联网、未调用模型。用户已批准四模型扩展对比和本轮 1 元费用上限；模型调用、预算闸及结果由项目运行器负责。

已从本机 `resources.assets` 复建并核对 300 个可见文本字段：180 条对白片段、60 条定向难句、60 条界面/资料。共有 21,195 原文字符、4,050 英文词，分 26 批。与旧 40 条样本的规范化原文交集为 0，新样本内部规范化原文重复为 0。规范化只合并空白，保留大小写和富文本标签。

## 选样依据

180 条对白来自 16 个真实连续片段：卫兵与王子、两次花园散步、女士们的差事、贝尔纳多告别、母亲墓前回忆、王后与厨娘、三次船员交谈、父亲训诫。每个片段内按真实脚本顺序选取；不同片段、不同日期和不同场景均独立成批，不能称为一次完整对话。片段长度为 2–23 条。

墓前回忆只选奥菲莉娅尚未知纪念日的 `else` 路径；父亲训诫只选第一轮路径，排除第二轮和返场。花园及厨娘片段在条件汇合后开始；其只读前文明确取一条兼容路径。找书场景按连续子片段拆开，原文件两处只有省略号的对白未列为翻译目标。其余片段中没有改变对白顺序的分支。

60 条难句分成 6 批，覆盖名句改写、歌谣、忏悔、祈祷、讥讽、否定、亲属关系、丧亲委婉表达、循环和时态自我修正。它们是定向挑战句，不是假定连续发生的完整对话。每条保存原始邻近脚本证据；给模型的只读前一句在条件界线处停止回溯，避免串入互斥前文，也避免重复发送大量相邻脚本。

60 条界面/资料分成 4 批，包含 7 个分类标题、15 个资料标题、20 个长资料字段、10 个信念标签和 8 个初始角色简介。资料标题和长字段按分类轮流选取，覆盖宫廷、政治、海上、超自然、城堡往事等内容；不只截取原文件开头。保留奥菲莉娅视角、换行、传闻程度和程序条件边界。

## 输入与提示约定

- `inputs/`：VNText 的 `name` / `message`；无说话人的资料省略 `name`。
- `manifest.json`：真实 ID、资产哈希、行号、原始行、对象路径、文件及数组位置、语体、只读背景；用于在工具丢失元数据后恢复来源关联。
- `context.json`：每批片段、路径、兼容前文以及本游戏角色证据。
- `glossary.json`：继承旧小样暂定译名，尚未锁定正式术语；不借原著猜本游戏人物性别或婚姻身份。
- `system-prompt.txt` / `writing-style.txt`：逐字复制旧小样提示，保持自然易读中文、原文已有的适度戏剧感及忠实信息要求。
- `rules/`：通用模型使用中文 `world_building_content`；Qwen-MT 原生协议使用英文 `qwen_mt_domains`。两者使用相同来源、同一背景事实和同一暂定词表；协议不同，不能宣称提示字节完全相同。
- `source-verification.json`：本地源文统计和来源资产哈希，记录模型调用数为 0。

## 复建与核验

在项目根目录运行，依赖项目已有的离线 Python 提取环境：

```powershell
python translation/trial-expanded-2026-10-09/prepare_inputs.py
python translation/trial-expanded-2026-10-09/verify_inputs.py
python -m unittest discover -s translation/trial-expanded-2026-10-09 -p 'test_*.py'
```

复建脚本只写本目录的输入及规则文件，不修改游戏资源、旧 40 条译文或新轮输出。已付费后，应先用核验脚本检查冻结输入，再决定是否有必要复建，避免无意改变对比条件。

核验逐项重新读取真实游戏资源并解析字段，检查资产哈希、原文哈希、原始行、对象路径、角色名称、输入顺序、来源 ID、数量及新旧去重。回归测试覆盖原文被修改、VNText 顺序被交换和重复旧样本的拒绝行为。

这是有目的的覆盖选样，不能用它估计全量游戏的总体错误率；最大静态候选资源仍未动态确认为游戏实际加载版本。输入制备与模型质量评估、游戏内对白排版是分开的验证。
